# 닥터온 재고관리 자동화 (dr-on-inventory) v0.3

뉴트리정 재고관리 스킬의 **현행 운영 로직**을 베이스로 닥터온 브랜드에 맞게 분리한 스킬. 뉴트리정과 시트 구조(헤더·6행 블록)는 동일하나 시트 ID, 사방넷 계정·코드체계, 상품 목록, 작업요청 시트, 박스/파레트 스펙이 전부 다르다. **뉴트리정 요청에는 절대 이 스킬을 쓰지 않고, 뉴트리정 값(시트ID·N002 코드·스펙)을 닥터온에 대입하지 않는다.**

- v0.2 (2026-09-02): 사방넷 prefix E004 확인, 작업요청 시트 8탭 세팅, hg.kim 웹앱으로 입력 경로 교체, 스펙 3종 확정.
- v0.3 (2026-09-09): 사방넷 등록 4종 코드 확정, 맥주효모 스펙 확정, **그로스 행 순서 재배치 반영**, **그로스 시트에 수식이 0개임을 실측**, 사방넷 상품명 필터 요령 추가.

### 시트 입력 API 사용법
```javascript
var API="https://script.google.com/macros/s/AKfycbwJ8fOXA0IAMRHTxnp0Lg1DdJD5jStHi8_5EWswAN0fW9FCZfDh4hl9maxBgUWOcxXD/exec";
var GROS="1j4iRHiTiEt6_YzkrejvFCOs-wrBpbhGSna4E3irvFcg", JAK="1aK8Wg-8irrglyt7gHs3XmfDmhVhsK0CXLlDUb-n5y4Y";
function post(p){return fetch(API,{method:'POST',mode:'no-cors',body:JSON.stringify(p)});}
// 셀 쓰기 (sheetId 생략=닥터온 그로스, sheetName 생략="그로스 재고 DB")
post({action:"updateCells",sheetId:GROS,sheetName:"그로스 재고 DB",updates:[{cell:"AD63",value:5000},{cell:"AE63",value:"2028. 8. 23"}]});
post({action:"updateCells",sheetId:JAK,sheetName:"브로멜라인, 맥주효모",updates:[{cell:"A3",value:"브로멜라인 0915"}]});
post({action:"clearRange",sheetId:JAK,sheetName:"이노시톨",ranges:["C6:C11","B15"]});   // 내용만 클리어
post({action:"duplicateSheet",sheetId:JAK,source:"이노시톨",newName:"새상품A, 새상품B",index:9}); // 신규 상품 탭 추가용
post({action:"renameSheet",sheetId:JAK,sheetName:"이노시톨",newName:"이노시톨, 새상품"});
```
- 응답은 opaque → 항상 gviz/export CSV로 재확인. 120건 청크, 청크 사이 4초.
- 작업요청 시트 수식 셀(D/I열 6~11행, 12~14행) 절대 쓰지 말 것.

### ⚠️ 그로스 시트에는 현재 수식이 없다 (2026-09-09 실측)
`A1:CZ200` 전 범위 `ISFORMULA` 합계 = **0**. 판매단가확인 탭도 0, 판매 Data는 헤더만(쿠팡 미등록). 즉 O~X 계산기 열은 수식이 아직 안 깔린 빈 열이다.
- 따라서 현재는 **행 이동·순서 변경이 안전**하다(깨질 참조가 없음). 실제로 2026-09-09 사용자가 맥주효모 블록을 이동했고 AD/AE도 그대로 따라갔다.
- 단 **빅셀 연동으로 S/X 계산기 수식이 깔린 뒤부터는** 뉴트리정처럼 행 구조 변경이 위험해진다(X/Y/Z/AK 앵커 밀림 사고 이력). 그때는 사용자에게 먼저 경고할 것.
- 순서 변경이 필요하면 잘라내기+붙여넣기 대신 **행 헤더 드래그 이동**을 안내한다(서식·병합·조건부서식까지 따라감).

### 브라우저·읽기 요령
- 이더컴퍼니 사방넷 세션은 **크롬 Browser 3**(deviceId 929af19e…)에 살아 있다. Browser 2에는 없음(2026-09-09 확인). 연결된 브라우저가 여러 개면 사용자에게 물어보고, 고른 브라우저에 사방넷 로그인이 없으면 Browser 3을 먼저 확인해본다.
- Browser 3은 **스크린샷이 항상 타임아웃** → JS(`javascript_tool`)로만 조작. `find`/`read_page`도 Sheets·Apps Script 페이지에선 실패.
- Sheets 편집 탭에서 doPost 후 fetch를 이어 하면 렌더러가 자주 멈춤(45s 타임아웃) → **API 호출·CSV 읽기는 `https://docs.google.com/robots.txt` 를 연 가벼운 워커 탭에서** 실행 (docs.google.com 동일 출처라 export/gviz fetch 가능). 한 번에 45초 넘는 루프는 쪼갠다.
- **구조 파악은 `export?format=csv&gid=…`** (빈 행 유지) / 값 확인은 gviz (빈 행 드롭, 없는 탭명이면 첫 탭으로 폴백하니 탭명 오타 주의). CSV는 RFC4180 파서로(셀 내 줄바꿈).
- JS 반환값에 쿠키·쿼리 문자열처럼 보이는 텍스트가 섞이면 결과가 BLOCKED 된다 → 숫자·날짜·상품명만 추려 반환.

## 1. 재고 최신화 (사방넷 → AD/AE)

### 1-1. 사방넷 스크래핑
1. 재고조회(유통기한) 페이지 접속 후 **계정 확인**(상단 "고객사 이더컴퍼니님"). 로그인 페이지로 빠지면 사용자에게 **그 탭에서** 로그인 요청 (다른 탭·다른 브라우저 로그인은 세션이 안 넘어옴).
2. **출고상품명 필터에 `닥터온` 입력이 필수.** 필터 없이 조회하면 이더컴퍼니 공산품까지 32페이지가 나온다. 필터를 넣으면 닥터온 전 품목이 1페이지에 들어온다.
   - 출고상품명 input = `document.querySelectorAll('input')[6]`, 검색 버튼 = `document.querySelectorAll('button')[4]`
   - React 제어 input이므로 **네이티브 setter**로 값을 넣고 `input` 이벤트를 디스패치해야 먹는다.
3. 스크래핑 (검증된 형태):

```javascript
  var ct=cells[cells.length-1].textContent.replace(/\s+/g,' ').trim();   // 유통기한 셀
  var qc=cells[cells.length-2];                                          // 출고가능 수량
  res.push(cc+' | '+nm.slice(0,22)+' | Q'+qc.textContent.replace(/[^0-9,]/g,'')+' | RAW['+ct.slice(0,150)+']');}}
res.join('\n')
```
4. **유통기한 셀은 날짜와 수량이 붙어서 나온다** — 예 `2028-08-128,050` = 2028-08-12 + 8,050. 앞 10자가 날짜, 나머지가 그 배치 수량. 배치가 여러 개면 반복된다.
5. **출고가능만** 사용. 총재고·입고대기 제외. 재고 0인 품목은 AD/AE를 빈칸으로 둔다.

### 1-2. 행 매핑 확인 (필수)
스크래치 셀(EO열 250행 이후)에 수식을 API로 쓰고 export CSV로 읽는다. `ARRAYFORMULA(INDIRECT(...))`는 배열 미지원이라 오답 — **개별 셀 참조 TEXTJOIN**을 쓴다.

```javascript
// 검증된 형태: 상품명 + 블록합계 + 소비기한 한 번에
'=TEXTJOIN("~",0,"63:"&LEFT(B63,5)&":"&SUM(AD63:AD68)&":"&TEXT(AE63,"yyyy.mm.dd"),"81:"&MID(B81,5,6)&":"&SUM(AD81:AD86),"ALL:"&SUM(AD3:AD92))'
```
읽은 상품명과 사방넷 상품명을 **전체 대조**한 뒤에만 입력한다. 사용 후 스크래치 셀은 `clearRange`로 정리하고 비었는지 재확인.

### 1-3. AD/AE 입력
- 블록 6행에 배치를 **소비기한 오름차순으로 1차→6차** 채우고, 나머지 슬롯은 `""`로 클리어 (1차 소진 시 2차를 1차 자리로 당김).
- 수량 0인 배치는 넣지 않는다.
- 120건 단위 청크, 4초 간격.

```javascript
var BLK={63:[[5000,"2028. 8. 23"]], 75:[[8050,"2028. 8. 12"]], 81:[[5000,"2028. 8. 13"]], 87:[[6400,"2028. 8. 11"]]};
var ups=[];Object.keys(BLK).forEach(function(k){var s=parseInt(k),b=BLK[k];
 for(var i=0;i<6;i++){var r=s+i,v=b[i];ups.push({cell:"AD"+r,value:v?v[0]:""});ups.push({cell:"AE"+r,value:v?v[1]:""});}});
```

### 1-4. 검증
블록별 `SUM(AD…)` 합계를 사방넷 총 출고가능과 **전 품목 일치** 확인 후 보고. 리포트는 **현재 수량만** (이전값/변동 비교 표시 금지).

**최신화 이력**: 09-02 브로멜라인 5,000 / 알파CD 8,050 / 이노시톨 6,400 (맥주효모 0) → 09-09 맥주효모 5,000 추가, 합계 24,450.

## 2. 1개입 + 번들작업 수량 산출

### 규칙 (사용자 확정, 위반 시 입고 2번 잡혀 회당 10만원+ 손실)
1. **S열(계산기) 값 그대로 사용.** 예약 슬롯 수량 차감 금지. 계산기 = 이미 입고 잡힌 수량 + 지금 필요한 수량.
2. gviz로 S값 읽을 때 오독 방지: 새 스크래치 셀로 재조회해 두 번 일치할 때만 확정. 헷갈리면 화면 확인.
3. **재고 없는 품목은 스킵** (보관수량 0 또는 ≤100).
4. 작업 후 각 상품 보관 ≥ **100개 버퍼** 유지 (작업 ≤ 보관 − 100). 1개입 먼저 배정, 잔여로 번들.
5. 작업은 **해당 소비기한 배치 하나**에서 나간다 → 총 보관이 아니라 그 배치 수량으로 가능 여부 판정.
6. 사용자가 "널널하게" 선호. 라이브방송 등 이벤트 품목은 넉넉히.
7. 1개입 완파렛 = 개/파레트 수량. 소량 파렛 상품은 2~3파렛 고려.
8. 박스·파레트: 낱개 ÷ 개/박스 **올림** = 박스, 박스 ÷ 박스/파레트 = 파레트(소수). 합산 후 +1 여유 권장. 스펙 미확정 상품은 "스펙 확인 필요"로 표기하고 파레트 계산 보류.

### 판매 데이터가 없을 때 (닥터온 현행 상태)
쿠팡 미등록이라 O~X 열이 비어 있어 **S열 계산기가 작동하지 않는다.** 이 상태에서는:
- 계산기 대신 **사용자가 수량을 직접 지정**한다. 판매량을 추정해서 제안하지 않는다.
- 대신 각 상품의 **작업 가능 상한**(= 보관 − 100), **1개입 완파렛 수량**, 보관·소비기한을 표로 제시해 사용자가 고르게 한다.
- 첫 라운드는 1개입 위주로 시작하고, 번들 구성은 사용자가 지정한 세트 수만 반영한다.

### 산출 절차
1. 1개입 행 + 옵션 행의 S, R, O, AD, AE 를 스크래치로 읽는다 (상품명 동시 대조).
2. 상품별 표로 채팅에 먼저 제시: 상품 · 구성수량(1개입 N · 2개입 M세트 …) · 소비기한 · 낱개 합 · 잔여 보관.
3. 사용자 확정 후 시트 입력.

## 3. 시트 입력 (사용자가 날짜 확정 후)

### 3-1. 그로스 시트 슬롯 열
- Y2~AC2 헤더 확인 → 빈 슬롯 사용. 다 찼으면 지난 날짜 열의 **데이터만 클리어** 후 재사용 (열 삽입/삭제 절대 금지, Ctrl+H 금지).
- 헤더는 날짜 serial. 날짜 변경 시 헤더만 바꾸면 됨.
- 각 옵션 행에 세트 수 입력. 입력 후 스크래치로 `행:상품명:옵션:값` 읽어 **건수 전부 대조**.

### 3-2. 작업요청 시트 (에이투지) — `1aK8Wg-8irrglyt7gHs3XmfDmhVhsK0CXLlDUb-n5y4Y`
탭 8개, 탭당 상품 2개(좌 A~D / 우 F~I). K~N 3번째 블록은 차수용(현재 미사용). 그 외 `에이투지 수량`, `한미양행 출고마감` 탭은 손대지 않는다.

| 탭명 | 좌(A) / 그로스 행 | 우(F) / 그로스 행 |
|---|---|---|
| 올레샷, 유산균50억 | 올레샷 / 3 | 유산균 50억 / 9 |
| 구강유산균, 올리브오일 | 구강유산균 / 15 | 올리브오일 / 21 |
| 카무트효소, 대마종자유 | 카무트효소 / 27 | 대마종자유 1000 / 33 |
| 그레인버닝, 콘드로이친 | 그레인버닝 / 39 | 콘드로이친 / 45 |
| 글루타치온, 멜라토닌5mg | 글루타치온 / 51 | 멜라토닌 5mg / 57 |
| 브로멜라인, 맥주효모 | 브로멜라인 / **63** | 맥주효모 / **81** |
| 쏘팔메토, 알파CD | 쏘팔메토 / **69** | 알파CD / **75** |
| 이노시톨 | 이노시톨 / 87 | (없음) |

블록 셀 (실제 A1 주소, 빈 행 포함 — 뉴트리정 시트의 A21과 달리 스펙은 **20행**):

| 항목 | 좌 | 우 |
|---|---|---|
| 제목 "상품명 MMDD" | A3 | F3 |
| 현재 총수량 (해당 배치 보관 합계) | A6 | F6 |
| 세트 수 1~6개입 | C6:C11 | H6:H11 |
| 소비기한 "YYYY.MM.DD" | B15 (merged anchor) | G15 |
| 스펙 문구 "상품명 (1박스 N개 / 1파렛 M박스 = N×M개)" | A20 | F20 |
| 수식(건드리지 말 것) | D6:D11, C12:C14 | I6:I11, H12:H14 |
| 포장비 단가표 | E6:E11 | J6:J11 |
| 발주내역 | 25행~ (H25 라벨) | |

스펙 문구 입력 완료: 브로멜라인 A20 · 맥주효모 F20 · 알파CD F20 · 이노시톨 A20. 나머지는 "※확인 필요" 상태.

```javascript
function blk(side,title,total,sets,exp){
 var C=side==='L'?['A3','A6',['C6','C7','C8','C9','C10','C11'],'B15']
                 :['F3','F6',['H6','H7','H8','H9','H10','H11'],'G15'];
 var a=[{cell:C[0],value:title},{cell:C[1],value:total},{cell:C[3],value:exp}];
 for(var i=0;i<6;i++){a.push({cell:C[2][i],value:sets[i]===0?"":sets[i]});}return a;}
// post({action:"updateCells",sheetId:JAK,sheetName:"브로멜라인, 맥주효모",updates:blk('L',"브로멜라인 0915",5000,[2700,0,0,0,0,0],"2028.08.23")})
```
탭별 1.5초 간격. 입력 후 gviz(`sheet=탭이름&range=A3:H15`)로 남은수량(C14/H14) 음수 없는지 확인. 이번 라운드 대상이 아닌 블록은 건드리지 않는다(이전 라운드 값 잔존 가능 — 사용자에게 알림). 신규 상품이 늘면 `duplicateSheet`로 탭 추가 후 위 표·A20/F20 갱신.

### 3-3. 카톡 문구 (고정 양식)
```

상품명 (소비 2028.08.23) · 1개입 2700개
```

이 양식 외 형식(번호 매기기, 인사말 장문, 굵게)은 쓰지 않는다. 문구 뒤에 총 낱개/박스/파레트 한 줄.

### 3-4. 캡처 대조
사용자가 작업요청 시트 캡처를 보내면 세트 수·낱개·합계·소비기한을 카톡 리스트와 1건씩 대조. 총수량(A6/F6)이 옛 값이어도 사용자가 "실재고는 괜찮다"고 하면 작업수량만 체크.

## 4. 발주 (한미양행)
- X열(자동발주 계산기) 기준. MOQ 1개입 5,000, 5,000 미만이면 올림. 납기 발주일+30일.
- 발주 시 AG열에 `수량(MM/DD)` 기입. 부분 도착 시 잔량으로 갱신, 전량 도착·AD 반영 시 클리어.
- 발주서 생성만 하고 실제 발주는 사용자가.

## 5. 스펙·코드 갱신 (사용자가 입고 자료를 채팅으로 줄 때)
사용자가 "상품 / 내품수량(입수) / 유통기한 / PLT입수 / 총 수량" 형태로 보내면:
1. 0장 상품 블록 표의 개/박스·박스/파레트·개/파레트 갱신 (프로젝트 메모리 `reference_dr_on_product_specs`도 동일하게).
2. 작업요청 시트 해당 블록 A20/F20을 `상품명 (1박스 N개 / 1파렛 M박스 = N×M개)` 로 덮어쓰기 ("※확인 필요" 제거).
3. 유통기한은 배치 정보로만 기록. 그로스 AE열은 사방넷 재고조회 값이 우선(입고 반영 후).

용어: **내품수량 = 개/박스**, **PLT입수 = 박스/파레트**.

## 6. 운영 주의
- gviz는 빈 행/열을 드롭한다 → 행 인덱스 절대 추정 금지, 상품명 대조로 확인. 구조 파악은 export CSV.
- gviz가 hang 하면 시트 탭을 새로고침하거나 robots.txt 워커 탭에서 XHR로 재시도. gviz URL을 탭에 직접 열면 다운로드되어 chrome:// 로 빠지므로 **반드시 페이지 안에서 XHR**.
- 상품명 유사 품목(글루타치온/브로멜라인, 대마종자유/올리브오일, 유산균50억/구강유산균 등) 행 밀림 사고 이력 있음 → 값 넣기 전 상품명 전체 대조.
- 수식이 생긴 뒤에는 수식 셀 수정 금지. `#REF!` 발견 시 임의 복구하지 말고 사용자에게 먼저 알린다. Ctrl+H 전체 찾기/바꾸기 금지.
- 사방넷에서는 읽기만 한다.
- 파일 저장은 김현기 폴더. 스킬 수정 시 `김현기\스킬백업\dr-on-inventory`에 구버전 보관 (v0.1, v0.2, doPost_hgkim_v2.gs 있음).
