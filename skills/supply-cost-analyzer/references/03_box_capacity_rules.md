# 박스당 입수량 추정 원칙 (실측 + 예측 하이브리드)

## 왜 이게 중요한가

박스당 입수량은 **FBC+밀크런 개당 비용**을 결정한다. 박스당 입수량이 적으면 개당 비용이 커져 공급원가가 상승한다. 따라서 박스 한계에 가까운 값을 정확히 추정해야 한다.

## 문제

1차 발주·소량 발주는 **박스가 가득 안 찬 상태**로 출고된다. 관찰값만 보면 박스 한계를 과소평가하여 FBC+밀크런비가 과대 산출된다. 반대로 무조건 이론값을 쓰면 실제 박스 용량을 초과 추정해 비용 과소 산출 위험이 있다.

## 판정 기준 (우선순위 순)

| 관찰값 vs 이론값(75%) | 판정 | 채택 값 |
|---|---|---|
| 관찰 ≥ 이론 75% | **실제 확인** (박스 한계 증거) | 관찰값 |
| 관찰 ≈ 이론 75% (±5%) | **실제 확인** (한계 근접) | 관찰값 (더 큰 쪽) |
| 관찰 < 이론 75% (10% 이상 미달) | **한계 미확인** (덜 담긴 상태) | **이론 90% 사용** |
| 관찰값 없음 (신상품) | 이론값만 | 이론 90% |

## 이론값 계산 공식

```
박스 내부 부피 = 박스 길이 × 폭 × 높이 (cm³)
적재효율 = 90% (공격적) 또는 75% (보수적)
유효 부피 = 박스 부피 × 적재효율
상품 부피 = 외형(길이+여유 × 폭 × 높이)
이론 입수량 = 유효 부피 ÷ 상품 부피 (내림)
```

### 상품 외형 치수 예시 (슬리퍼)
- 길이 + 2.5cm (여유)
- 폭 = 뒤꿈치 너비 × 1.8
- 높이 = 6cm
- 박스 57×45×37 → 유효 부피 71,179 cm³ (75% 적재)

## 1+1 세트 옵션 변환

```
1+1 박스당 세트 = 1켤레 박스당 켤레 ÷ 2 (내림)
```

**CN 시스템은 항상 "낱개" 기준**. "박스당 30개"라는 표현이 있으면 그게 세트인지 낱개인지 반드시 확인:
- 박스 부피와 상품 크기로 검증
- 박스별 popover 수량 기준 확인

**실수 사례**: "1+1 30세트/박스" 표기 → 실제는 "30켤레 = 15세트" (박스 부피로 역산 시 세트 불가능)

## 실측 검증 트리거

다음 경우 메모리·DB 값 재검증 필요:

1. **대량 발주 시** 박스 popover로 실측 (소량 발주 데이터는 신뢰도 낮음)
2. **기존 DB 값이 1차 발주 기준이었다면** 후속 발주로 갱신
3. **1+1 관찰값이 1켤레 관찰값 ÷ 2보다 크면** → 1켤레가 박스 한계 아님 시사 (예: 1개 45, 1+1 50켤레 → 1개 실제 한계는 50)

## 색상·옵션 다른데 관찰값 다를 때

같은 SKU/같은 박스 규격이면 **색상 무관 박스 최대 용량 동일**이 원칙. 색상별 관찰값이 다르면:
- **최대값**이 박스 한계에 가장 근접
- 나머지는 "덜 담긴 박스"로 판단
- 단, 포장 방식이 실제로 다르면 예외 (드문 케이스)

## 예시 (슬리퍼 2026-04-23 실측)

| 사이즈 | 1+1 관찰(켤레) | 이론 75% | 판정 | 채택 |
|---|---|---|---|---|
| 225-235 | 40 | 51 | 미달 (78%) → 이론 90% | 61켤레 |
| 240-245 | 50 | 50 | 일치 → 실제 | 50켤레 |
| 250-255 | 42 | 43 | 근접 → 실제 | 43켤레 |
| 260-265 | 42 | 42 | 일치 → 실제 | 42켤레 |
| 270-280 | 40 | 40 | 일치 → 실제 | 40켤레 |

225-235만 이론 90% 예측, 나머지는 실측 확인.

## 진짜 "박스 최대 한계" 확인 방법

완전한 검증 필요 시:
1. **이론 부피 계산**: 상품 접힌 상태 × 입수량
2. **포화 발주**: 박스가 가득 찰 만큼 넉넉히 발주 후 실측
3. **CN 창고 문의**: 박스당 최대 입수 지침 확인

현재 DB 값은 대부분 "관찰된 최대값"일 뿐, 물리적 최대 한계는 아닐 수 있음. 보수적 추정이므로 실제 FBC+밀크런비가 다소 높게 산정되는 방향으로 작용.
